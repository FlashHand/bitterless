# Python and Go index exclusions

Owner request, 2026-09-07: supplement both Bitterless and Cowork OnlyPreview with common
Python/Go dependency and generated-directory exclusions. Bitterless is canonical; Cowork
receives the narrow port under `mini-018`, preserving ongoing host integration.

## Contract

- Extend hard directory names with Python `__pycache__`, `__pypackages__`, `venv`,
  `site-packages`, `htmlcov`; Go `vendor`, `go-build`.
- Exclude directories ending in `.egg-info` or `.dist-info` and their descendants.
- Exclude consecutive directory components `pkg/mod` and `pkg/sumdb` at any depth.
  Do not exclude ordinary `pkg`, `src`, `bin`, `env`, `mod`, or `sumdb` directories.
- Existing dot-directory exclusion already includes `.venv`, `.tox`, `.nox`, `.pytest_cache`,
  `.mypy_cache`, `.ruff_cache`, `.pytype`, `.hypothesis`, `.eggs`, and hidden Go caches.
  Do not redundantly add them or infer arbitrary environment paths from extra disk reads.
- Match directory components only, not similarly named regular files or path substrings.
  Normalize existing Windows separators. User negation rules cannot undo hard exclusions.
- Initial traversal/counting, watch and selected-file priority indexing share this policy;
  skip descendants before reading bodies. Files and Contents must not return excluded paths.
- Project browsing/direct preview remain available; existing orange exclusion markers inherit
  to descendants. No file deletion, root-wide hide, new Main I/O or dependency changes.
- Include the deterministic hard policy in the engine identity. Old persisted indices must not
  serve newly excluded content while replacing the index. Use the existing candidate/atomic
  promotion path once; after promotion, subsequent opens reuse the index normally.
- Custom cache/environment names remain governed by existing workspace ignore rules.

### Confirmed boundary defect during implementation

Focused runtime regressions reproduced a pre-existing type ambiguity exposed by the new names:
regular files `regular/vendor`, `regular/pkg/mod`, `regular/package.dist-info`, and
`regular/package.egg-info` were skipped by watch updates and rejected by search-result preview.
The shared untyped physical-path predicate treated the leaf as a possible directory.
Use known node kinds for search preview; for watcher events only stat an ambiguous leaf when its
ancestors are eligible. Excluded ancestors still prune immediately, without body reads or directory
enumeration. Limit the repair to `watch-reconciler.mjs` and `global-search-preview.mjs` consumers.

## Sources

- [Python venv](https://docs.python.org/3/library/venv.html): virtual environments contain
  their own package installation directories; retain ordinary `bin` source/script directories.
- [Python package formats](https://packaging.python.org/en/latest/discussions/package-formats/):
  `.egg-info` / `.dist-info` metadata directory conventions.
- [Go GOPATH](https://go.dev/wiki/GOPATH): default module and checksum caches live under
  `pkg/mod` and `pkg/sumdb`, so excluding all of `pkg` would be too broad.
- [Go Modules: vendoring](https://go.dev/ref/mod#vendoring): `vendor` contains dependency copies.
- [Python compiled modules](https://docs.python.org/3/tutorial/modules.html#compiled-python-files):
  `__pycache__` stores generated bytecode.
- [Go build cache source](https://go.dev/src/cmd/go/internal/cache/default.go): `go-build` is
  the default cache basename; arbitrary `GOCACHE` overrides are not guessed.
